# Retail Sales & Customer Analytics using Python and NumPy

A complete, beginner-to-intermediate Data Analyst portfolio project that
turns a raw retail sales dataset into business KPIs, visual insights, and
an interactive dashboard — built primarily with **Python and NumPy**.

## Project Overview

This project simulates a real Data Analyst workflow: a retail company has
transaction-level sales data and needs it turned into decisions. The
project takes a raw, intentionally messy CSV file through data cleaning,
NumPy-based numerical analysis, KPI calculation, visualization, and a
deployed interactive dashboard.

It is designed as a **first full portfolio project** for students who have
just completed Excel, SQL, Python basics, and NumPy.

## Business Problem

A retail company sells products online across multiple Indian cities.
Management has raw order-level data but no simple way to answer basic
questions: which products and categories sell best, which cities and
regions are strongest, who the most valuable customers are, and how sales
and profit trend month to month. This project answers those questions.

## Objectives

- Practice real NumPy usage on a realistic dataset (not toy examples)
- Learn a complete Data Analyst workflow: raw data → clean data → analysis → insight
- Connect NumPy concepts to SQL `GROUP BY` and Excel formulas already learned
- Produce visual, KPI-driven output a non-technical manager could read
- Build a project suitable for GitHub, a resume, and beginner interviews
- Deploy the analysis as a small interactive web app

## Dataset

`data/retail_sales.csv` — approximately 2,000 rows of simulated retail
transactions, generated by `data/generate_dataset.py`. It intentionally
includes realistic data-quality issues (missing values, a few negative
quantities, duplicate order IDs, inconsistent category text, extra
whitespace, a couple of invalid dates) so cleaning is a real, practiced
step rather than a formality.

### Dataset Columns

| Column | Description |
|---|---|
| Order_ID | Unique identifier for each order |
| Order_Date | Date the order was placed |
| Customer_ID | Unique customer identifier |
| Customer_Name | Customer's name |
| City / State / Region | Location of the order |
| Category | Product category |
| Product | Specific product name |
| Quantity | Units purchased |
| Unit_Price | Price per unit before discount |
| Discount | Discount applied (decimal, e.g. 0.10 = 10%) |
| Sales | Revenue after discount |
| Cost | Cost of goods for the order |
| Profit | Sales minus Cost |
| Payment_Mode | Payment method used |
| Customer_Type | New or Returning customer |

## Project Workflow

```
Raw CSV
  → Understand the business problem
  → Load data (pandas read, then convert to NumPy arrays)
  → Clean data (missing values, duplicates, invalid values, text formatting)
  → NumPy-based statistical analysis
  → Business KPI calculation
  → Boolean-mask filtering
  → Group-style aggregation (NumPy equivalent of SQL GROUP BY)
  → Visualization (Matplotlib)
  → Business insights & recommendations
  → Interactive Streamlit dashboard
  → GitHub repository
  → Deployment (Streamlit Community Cloud)
```

## NumPy Concepts Used

`np.array`, `np.arange`, `np.mean`, `np.median`, `np.min`, `np.max`,
`np.sum`, `np.std`, `np.percentile`, `np.unique` (including
`return_counts`), `np.sort` / `np.argsort`, Boolean masking, `np.where`,
`np.concatenate`, `np.vstack`, `np.hstack`, `reshape`, broadcasting, and
vectorized arithmetic. See `notebooks/retail_sales_analysis.ipynb`
Sections 7–15 for a fully worked, explained example of every concept
listed above, applied directly to this dataset.

## Data Cleaning

Applied in `src/data_loader.py -> clean_data()`:
1. Strip extra whitespace from text fields
2. Standardize inconsistent Category text
3. Remove rows with missing Quantity, Unit_Price, or Order_Date
4. Remove invalid (zero/negative) Quantity
5. Remove duplicate Order_IDs
6. Recompute Sales/Cost/Profit from cleaned source values
7. Parse and validate Order_Date

Roughly 150 of ~2,000 rows are removed by these rules — expected, given
the issues were injected on purpose for practice.

## KPIs

Total Sales, Total Profit, Total Orders, Total Customers, Total Quantity
Sold, Average Order Value, Profit Margin % — all calculated in
`src/analysis.py` and shown live in `app.py`.

## Analysis Performed

Basic KPIs, descriptive statistics (mean/median/std/percentiles),
Boolean-mask filtering (high-value orders, profitable vs. loss-making
orders, high-discount orders), category/product/city/region/customer
aggregation (SQL-`GROUP BY`-style), repeat-customer rate, and
month-by-month sales and profit trends. Full detail and business framing
for each is in the notebook.

## Visualizations

1. Monthly Sales Trend (line) — is revenue growing, shrinking, or seasonal?
2. Sales by Category (bar) — which category earns the most revenue?
3. Profit by Category (bar) — which category is most *profitable*?
4. Top 10 Products (horizontal bar) — what should we prioritize in inventory?
5. Sales by Region (bar) — which regions are strongest?
6. Orders by Customer Type (pie) — how much of our business is repeat customers?

## Key Insights

Generated directly from the calculated data in
`notebooks/retail_sales_analysis.ipynb` Section 16 — figures will differ
slightly each time the dataset is regenerated, since the data uses a
random seed but real-world data would differ project to project. The
notebook explains the difference between an **observation** (a plain
fact), a **business insight** (a fact plus why it matters), and a
**business recommendation** (a specific resulting action) — an important
distinction for Data Analyst interviews.

## Business Recommendations

1. Prioritize inventory and marketing budget toward the top-performing category and city.
2. Investigate the weakest-profit region for pricing, cost, or discount issues before cutting investment there.
3. Build a retention or loyalty offer targeted at top customers by revenue.
4. Review high-discount, low-profit-margin products.
5. Study any gap between the best sales month and best profit month to understand discount timing effects.
6. Track the repeat-customer rate over time as an ongoing loyalty health metric.

## How to Run Locally

### Installation

```bash
git clone https://github.com/<your-username>/retail-sales-numpy-analysis.git
cd retail-sales-numpy-analysis
python -m venv venv
source venv/bin/activate      # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

### Run the notebook

```bash
jupyter notebook notebooks/retail_sales_analysis.ipynb
```

### Run the dashboard

```bash
streamlit run app.py
```

Streamlit will open the dashboard in your browser, typically at
`http://localhost:8501`.

### Regenerate the dataset (optional)

```bash
python data/generate_dataset.py
```
